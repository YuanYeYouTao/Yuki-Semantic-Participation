# 长时静默自主发言与无 @ 连续接话：代码核查和实现方案

日期：2026-09-23。此文按当前需求评估代码；旧任务书是历史设计材料，不限制这里的目标。本文没有修改运行逻辑，没有使用真实聊天正文，也没有验证线上发送。

> 设计更新：下表中的随机回忆概率、旧观察队列参数仅是实施前基线。当前控制器已取消随机累积门槛；合格语义候选直接提出机会，当前参数见 [实施状态](implementation.md)。

> 本文前面的“当前代码”表格是实施前基线。随后两仓库在开发分支完成了无来源 `intrinsic`、无近期真人记忆扫描、确认出站消息的内部线程映射与无引用 SELF 锚点选择；当前仍未上线。参数为实验值，真实发言次数须以发送回执测量。

## 目标

1. 群里长时间无人发言时，Yuki 仍可凭已有记忆、自己的状态，或者没有外部内容来源的内部动机启动一次 SELF 回合；主 Agent 决定发言、行动或 `NO_REPLY`。
2. Yuki 实际发言后，真人自然续聊无需每条 @ 或引用 Yuki。多人交错、转话题、明确结束时仍能正确判断归属。
3. 自主机会不冒充真人输入或 Jev 观测。群授权、唯一 owner、generation、工作占用、持久幂等和实际发送权限仍由宿主核验。不以每日次数配额控制行为。

## 当前代码的事实

| 环节 | 当前行为 | 对目标的影响 |
| --- | --- | --- |
| 定时推进 | Yuki `SemanticParticipationService._loop` 约每 2 秒 `tick`；控制器能在无新入站时推进已有候选。 | 短时延迟接话已经具备。 |
| 记忆来源 | `_seeds` 仅在控制器保有最近 600 秒真人事件时扫描；`_hydrate` 跳过更旧事件，控制器也只保留约 600 秒的细节。 | 长时静默没有新的 recall/contact 候选，放大发言概率不起作用。 |
| 回忆概率 | `dynamics.rate` 对 recall/contact 的强度上界为 `1/1800 s⁻¹`；种子语义支持有效期 180 秒。 | 单个持续合格种子的理论提议概率上界约 9.5%。用现有合成种子、2 秒数值积分得到约 2.94%，只是离线参数示例。 |
| 没有内容来源 | `Controller.rates` 只遍历候选；无候选时返回空。`Proposal` 必须携带语义 `Support`；宿主 `AcceptedInitiative` 必须有 event/memory 来源，semantic 接纳必须有 `support_refs`。 | 当前无法表达“无外部内容来源的内部发言动机”，需要新增明确的提议/接纳类型。 |
| 无 @ 的引用续聊 | `reply_to_event_id` 指向真实 Yuki 消息时，控制器可记录 `matching_self_anchor`。 | 有引用的场景有明确来源路径。 |
| 无引用的自然续聊 | 宿主的 `unit_options` 只取近期真人消息，不提供近期 Yuki 发言作为候选锚点；`matching_self_anchor` 仅由显式引用建立。 | Jev 即使判断 `extend_yuki`，控制器也不会把这条话计为已确认的“回应 Yuki”。实际合成单元对照中，同一 thread、上下文含 Yuki 发言但没有引用，`matching_self_anchor=None`，对应互惠分量为 0。 |
| SELF 出站的讨论归属 | 直接答复可借 `caused_by_event_id` 继承真人 thread；自主 SELF 发送不一定有该事件原因，出站消息可能被投影为自己的新 thread。实际发送回执的 `actual_targets` 是群，而原提议的 target 可能是某个人。 | 自主开话题后，后续无引用真人回复尤其容易失去同一讨论归属；目标级参与状态也可能无法得到发送回执。 |
| 语义队列 | 非活跃时去抖/最小间隔为 30/90 秒，conversation 焦点 90 秒过期；近全量合成回放有 5,277 条待评焦点过期。 | 高频群可能漏掉连续接话；现有汇总未区分漏掉的是哪类无 @ 机会。 |

代码位置：独立库 `controller.py`、`dynamics.py`、`scheduling.py`、`models.py`；Yuki 宿主 `services/semantic_participation.py`、`services/participation_feedback.py`、`conversation/autonomy_binding.py`、`conversation/autonomy_repository.py` 和 `social/service.py`。上述数值来自当前工作树及 `group-chat-workload-v2-replay.json`，不是线上发言率。

## 实现方案

### A. 先接通 Yuki 发言后的自然续聊

1. 将每条**已实际发送并入账**的 Yuki 群消息关联到其 SELF run、讨论 thread 和被面向的参与单元。直接答复可沿真实 `caused_by_event_id`；自主发言由已接纳 proposal/run 的 thread 建立持久映射。恢复或多段发送时使用内部事件 ID 与实际发送回执去重，不用平台消息 ID 猜归属。
2. 构造真人消息的 `unit_options` 时，在相同群和有效上下文内提供最近的 Yuki 发言锚点，包括自主发言；显式引用优先。多个话题同时活跃时保留候选和 `unknown`，不自动认定最后一句一定在回应 Yuki。
3. Jev 的快照保留被考虑的 Yuki 锚点与相邻真人上下文。对无引用消息增加可验证的“回应哪条 Yuki 发言/不确定”选择，答案只能引用宿主提供的内部锚点。控制器只在选择与 `extend_yuki`、发言机会判断相容时更新互惠状态；不伪造回复关系，也不把模型猜测写成平台引用。
4. 快照容量和队列优先级要保护正在进行的 Yuki 往返及明确停止/结束焦点。先修“停止消息已到达但尚未评分时旧候选仍提出机会”的竞态，再调整观察间隔。缩短间隔可提高覆盖，但必须同时记录 Jev 调用量和错误机会。

### B. 让长时静默仍能发现合法记忆候选

将“最近 600 秒真人事件”从群/SELF 记忆扫描的必要条件中移除。宿主按已有获准群、持久前行游标、来源修订和 lineage 有界扫描；联系某人的候选另核对目标依据。新记忆或未考虑过的旧记忆可在无人发言时交给 Jev 判断是否适合此群，`unknown` 或不适合就保持沉默。支持有效期和强度应成组校准，避免 180 秒短窗口配 `1/1800 s⁻¹` 造成几乎总是错过。

### C. 增加真正无外部内容来源的内部动机

新增与 conversation/recall 并列的 `intrinsic` 提议类型。它由宿主授权的时钟状态驱动，可参考距上次真人消息、Yuki 上次实际发言、既有 SELF 状态及本群运行反馈；**不要求** event/memory 焦点，也不伪造一条聊天事件或 Jev 的 `seed_fit` 结果。控制器可为它积累独立的有限强度；没有外部候选时仍可能提出机会。

宿主接纳时以 `proposal_id`、群 generation、owner/epoch、有效期和持久的内部动机尝试标识做原子防重，核对群授权、Presence、唯一活动 Work 及明确停止状态。当前 `AcceptedInitiative.sources` 非空、`InitiativeSourceKind` 仅 event/memory、semantic `support_refs` 非空的契约都要增加**明确的 intrinsic 分支**；不要塞入假的 event/memory ID。SELF 主 Agent 沿现有 `SelfInitiativeTrigger → Work → send_message / NO_REPLY` 运行，动态提示说明这是 Yuki 自己的机会，没有真人请求；允许工具行动或静默。`NO_REPLY`、实际发送及中断分别反馈，影响下一次机会的间隔和强度，不设置每日发言额度。

## 参数与代码边界

- **只调参数可做：**改变已有邀请后的等待分布、提高已合格回忆种子的提议机会、缩短 Jev 观察队列间隔。
- **只调参数做不到：**在没有候选时让当前 `rates()` 非零；让无引用真人续聊自动取得 Yuki 发言锚点；让现有宿主接纳零 event/memory 来源的 proposal。这三项需要代码和持久契约变更。
- 完成长时静默能力后，应通过回放和宿主影子实验校准，而不是先指定每天必须说几次。稀疏群允许长期沉默，也允许偶发的自主发言。

## 两仓库同步交付约束

本功能跨 `Yuki-Semantic-Participation` 与 `Yuki-QQbot`。不能只修改、验证或交付其中一边。当前核查时独立库 `main` 是 `6bbaff3f6c04d820fc3ade9ecb5ac42ee48f9dd3`，而 Yuki 的 `pyproject.toml` / `uv.lock` 仍固定引用独立库 `4d91e39070c2811032cce70c66ed8c82fced9058`；后续测试不能靠临时 `PYTHONPATH` 覆盖依赖来掩盖版本差异。

实施顺序应是：先定义并验证独立库的新提议/观测契约，再在 Yuki 同步更新宿主映射、接纳持久化、迁移、回执、固定依赖提交与锁文件；最后在**实际锁定版本**上运行两仓库各自测试和跨仓库影子回放。需要能够指出相互匹配的两个提交和接口版本。若工作分成多个提交，阶段边界必须保持可安装、可回退；不能把仅一边通过测试称为功能完成。

## 验收

1. 真实 SELF 发送后，同人/他人不 @、不引用的自然续聊可归到正确 thread；明确引用仍可用；别人之间的相似话题、转题、已结束、停止均不得误判为继续回应 Yuki。
2. 跨数小时无真人消息、有获准群记忆时可提出 recall；无记忆时仍可经 intrinsic 提出机会。两者分别标记，不能把 `intrinsic` 伪装成 Jev 支持的回忆。
3. 在无新消息、重启、owner 切换、群禁用、来源撤回、重复 tick、发送回执迟到和活动 Work 占用下，不重复接纳或发送，不借用真人权限。
4. 记录候选、Jev/unknown、提议、宿主接纳、主 Agent `NO_REPLY`/工具/拟发送、真实发送；按“Yuki 实际发言后的无 @ 续聊应接率/误接率”和静默间隔分桶报告。先跑隔离发送记录器，再做获准的小群验证。
