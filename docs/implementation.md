## 必须保持的边界

1. Host 传入已入库、已授权的有限材料，canonical 身份与 generation 由 Host 管理。平台消息号不是执行所有者。
2. 观测须对应原始 scope、焦点、版本与序号。context 只是解释依赖，不自动成为已评分焦点。
3. 撤回或修订来源会撤销其解释、依赖解释及预测。停止记录独立于原文窗口存活；重开必须有新证据。
4. `advance` 只返回机会。先持久检查点，再原子接纳并反馈真实 run；不确定时查询原 proposal，不换 ID 重跑。
5. epoch 约束新接纳，generation 与原执行授权继续约束已接纳工作；真实迟到效果可登记但不能复活终态。
6. 合法 unknown 不等于失败；必需维度非法、本地输入过大、未发出 HTTP 和 Provider 故障分别诊断。
7. 主 Agent 工具名称、schema、顺序与固定前缀保持一致，SELF 权限在执行处核验。动态来源只进入后部材料。
8. 新接纳写事务不等待模型/网关、不扫描历史。SnapshotStore 不跨线程共用连接。

## 工程参数

- 活跃候选最多 32；详细来源最多 256 条且正文合计最多 256 KiB。
- 观察队列最多 64 个焦点；同源修订合并，不以最新消息覆盖同讨论中的旧邀请。
- 默认非活跃去抖/间隔/最长等待为 3/12/20 秒，活跃时为 2/8/15 秒。conversation 未评分焦点在事件后 75 秒过期。
- conversation 观测必须在源事件后 90 秒内完成；合格支持到 `min(源事件+150 秒，评分完成+75 秒)`。seed 为源事件后 180 秒，引用短预测最多 45 秒。这些参数尚未经过生产校准。
- 主动邀请、继续邀请及面向群体的开放发言经 Jev 分类后可直接形成候选；`information_state=unknown` 不单独否决明确邀请。没有合格语义观测时保持沉默。
- 小快照最多六条 context；默认全请求 16,000 UTF-8 字节。先去非关键完整 context，仍过大则本地诊断，不能截断焦点或关键引用。
- 局部重算窗最多 10 分钟；容量裁剪可能缩短窗口，数值基线单独保存。
- 控制器快照默认每 scope 1 MiB、总计 16 MiB，超限显式报告；不等于主 Agent 的历史预算。
- Yuki seed 每次扫描有界，按 `(max(updated_at, valid_from), id)` 持久前行；空的无合法 lineage 页也推进，新增 evidence 更新 fact 变更时间。
- 默认 κ=0。开发分支已删除旧 `rates()`/`rate()` 及固定静默条件；非请求式 proposal 由[连续净机会值](autonomous-evolution.md)决定。无来源 `intrinsic` 的自身恢复与本群互动痕迹共同演化；长期没有新的真人互动时公开机会值趋负。请求间隔和来源防重不是每日发言额度。

## 定向工程验证

独立库覆盖概率/unknown、来源撤回、引用依赖、停止/重开、对象歧义、短预测、候选聚合、
多焦点公平性、局部重算、状态裁剪、请求容量、队列恢复、部分非法响应与健康降级。
这证明具体工程约束，不证明中文语义质量。

Yuki 定向覆盖真实数据库接纳防重、busy 不消费、多来源完整性、主开关和模式切换、缺 key 与合法 unknown、
慢观察不占全局锁、memory-only seed、generation 拒绝、原 Presence/Work 恢复及 SELF 工具与记忆边界。
工具回执、静默自省、质量与 lineage 检查有独立回归。现有数据库迁移按 Yuki 当前链追加至 0068，
本库不内置或管理这些表。

主 Agent 请求对照使用两种 Provider 实际序列化协议与 Responses 原生工具结构，并覆盖第 24 次请求后续跑。
这验证前缀/续跑结构；没有因此得到线上缓存命中率或真实主模型社交表现。

## 有限真实 Jev 验证

所有实测均为显式运行、顺序请求、无自动重试的开发者合成材料，没有真实聊天和 QQ 发送。
样本期望不是独立人工标注，也不是盲测；不得将匹配计数写成中文准确率。

历史 `v6-zh-1` 探针总计 14 请求。前 7 次发现投影含语义样本 ID、5 次输入超过 1,200 token，
不适合作为盲测。去掉本地管理字段、采用中性引用后重测同七例：输入合计 7,575，输出 1,677；
单次输入 1,003–1,120、均值约 1,082，较旧投影少约 13.7%；约 800 的目标未达到。
耗时 0.321–1.081 秒，中位约 0.355 秒，17 个开发者预设维度中 14 个吻合。
这些是旧 rubric 的诊断数据，不能代表当前版本或服务 SLA。
见 [v1 脱敏合成证据](evidence/jev-smoke-2026-09-22.json)。

本轮 `v6-zh-4` 又明确单独呼唤 Yuki 可算邀请；下表仍只代表旧 `v6-zh-3`，不能推断新版准确率。

## 离线工程对照与仍缺的验收

`scripts/replay_shadow.py` 将同份合成 fixture 送入真实 legacy 纯评分器、静态语义门控和动态 Controller，
由开发者期望生成 one-hot 语义观测，共用记录型 NO_REPLY 执行器。它不调用 Jev 或主模型，不发送 QQ。
[离线报告](evidence/shadow-synthetic-2026-09-22.json)记录输入、虚拟时间、随机种子、代码哈希与分支结果；
其版本仅对应报告所记代码快照，不能作为以后修改的自动验收。结果差异不证明动态方案更优。
