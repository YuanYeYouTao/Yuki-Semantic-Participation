## 必须保持的边界

1. 宿主把已入库、已授权的有限来源传给控制器。Person/Space/Conversation ID 是宿主的身份，平台消息号不是执行所有者。
2. `observe_committed_event` 的来源和 `apply_semantic_observation` 的快照必须匹配；context 是解释依赖，不自动算作已评分焦点。
3. 失效某条来源时，其解释、依赖它的解释和派生预测都失效。停止记录的生命周期独立于原文窗口。
4. `advance` 返回的是未执行提议。宿主先持久化控制器检查点，再原子接纳；成功后必须回传真实 run。结果不确定时按 proposal 查询，不能换 ID 重提。
5. `controller_epoch` 只控制新接纳；真实已接受回合的迟到反馈仍登记，不借此恢复已取消工作。
6. 部分非法响应与合法 `unknown` 区别对待。本地输入过大、未送出 HTTP 与 Provider 故障也分别记录。
   `unknown` 为维度最高概率（含并列）时不生成确定资格或停止边界；软状态仍按完整分布混合。
7. SnapshotStore 是单线程同步存储，调用者不得跨线程共享连接，也不得在其事务内等待模型或宿主操作。

## 工程参数

- 活跃候选最多 32；详细来源最多 256 条且正文合计最多 256 KiB。
- 局部重算窗最多 10 分钟；容量裁剪可能缩短这个窗口，数值基线单独保留。
- 快照默认每 scope 1 MiB、总计 16 MiB，超限明确报告；不同于宿主的 Agent 历史预算。
- conversation 当前 floor 支持源时效为 90 秒，seed 为 180 秒，预测仍最多 45 秒；这些是未校准实现参数。
- 新回忆/联系只能使用直接语义支持。不会靠长时间沉默制造新依据。
- 请求间隔、容量边界、指数强度及局部防重入都不是每日发言额度。

## 审查中修复的问题

本轮交叉审查发现并添加回归：上下文撤回没有传递失效、旧语义重评分后预测与注意残留、

另核对了原文过窗后的停止撤回与终态后的迟到真实发送效果。
首次收到原执行终态时也登记已考虑来源，防止重启查询跳过 accepted 回执后再次提议。
同一回执内冲突 effect ID 原子拒绝；活动与效果痕迹在裁剪前折叠为有界基线；
开口间隔采用当前可信讨论单元的最近真人片段，自己的输出不重置它。

复核的是这些确定的实现性质，不包含真人社交效果验证。

## 有限真实 Jev 验证

2026-09-22，固定 `jev-1.13.0` / `v6-zh-1`。总计 14 次顺序 HTTP 请求，无自动重试、
无真实聊天、无 QQ 发送。前 7 次用于发现协议和请求体问题：输入合计 8,777 token，
其中 5 次超过 1,200；事件 ID 含样本标签，不能用于盲测评价。

移除本地管理字段、改用中性引用后，重新验证同样的 7 个合成样本。完整原文与引用锚点保留，
固定 rubric 没有为匹配样本而修改。实际结果：

- 7/7 请求返回合法完整结构；输入合计 7,575、输出 1,677 token。
- 输入每次 1,003–1,120，平均约 1,082，较原投影约减少 13.7%。约 800 的目标尚未达到。
- 耗时 0.321–1.081 秒，中位数约 0.355 秒；小样本不是服务 SLA 或长上下文性能结论。
- 17 个开发者预设维度中 14 个吻合；3 个必需维度共 21 项中有 2 项选择 unknown。
  这些期望不是独立人工标注，不能将 14/17 当作真实中文准确率。
- 分歧包括结束范围、其他人对话和缺指代时的信息变化。离线重放显示，他人对话的 act/floor
  冲突被挡住；“已解决”的群级范围则确实成为了群级边界，仍需校准和独立标注。

公开的[脱敏合成证据](evidence/jev-smoke-2026-09-22.json)保留完整概率与上述分歧。
长材料、六条上下文、记忆/联系适当性和生产流量尚未在这批请求中验证。
